    01
    Theory

    1.1 Statistical disclosure control

    Theory

    • Primary suppression: sensitive cells that need protection according to the statistical agency’s policy
      • Should be protected against disclosure and inference
    • Secondary suppression: valid cells whose suppression is needed so that it is not possible to differentiate primarily suppressed values (example.)
      • Secondary suppressed cells must be protected against disclosure
    • A protection interval is ensured on primary suppressed cells only.

    With rtauargus, it is possible to compute the primary suppression during the tau-Argus call, but we do not encourage it because of the way tab_multi_manager() works. We prefer to compute beforehand variables that allow to track primary suppression rules all the way to the final product.

    1.2 Context and objectives

    Theory

    • Statistical agencies often disseminate multiple related tables describing the same phenomenon.
    • Some tables share common cells that must be protected consistently.
    • Protecting each table independently may lead to disclosure risks when information is combined across tables.
    • The challenge becomes even more complex in the presence of non-nested hierarchies.


    In this tutorial, we focus on:

    1. Preparation: using rtauargus (and tau-Argus) require some preping work on data and metadata.
    2. Parameters: rtauargus is efficient as long as parameters are used knowingly.

    1.3 Linked tables

    Detecting Links Between Tables

    When are tables considered linked?

    Tables are linked when they cover compatible statistical fields and share information that can be combined or used to derive confidential values.

    This may occur when:

    • They share the same indicator and statistical field:
      • Without common breakdown variables, they share their grand total;
      • With at least one common breakdown variable, they share one or more margins or cells.
    • Their indicators are connected by a mathematical relationship, allowing values in one table to be derived from values in another.

    Tables covering distinct, non-complementary statistical fields are considered independent.

    1.4 Common relationships between linked tables

    Detecting Links Between Tables

    Common relationships between linked tables

    • Shared grand totals: tables share the same overall total, example.
    • Common margins: tables share categories of the same explanatory variable, example.
    • Linear relationships: indicators across tables are linked by mathematical equations, example.
    • Hierarchical classifications: categories are structured into nested levels, example.

    02
    Tools

    2.1 τ-Argus

    Tools

    τ-ARGUS is a software program designed to protect statistical tables.

    • A long-standing reference in the SDC tools landscape
    • Developped mostly at CBS (Netherlands)
    • Current version is open-source
    • Runs on Windows only

    2.2 The rtauargus package

    Tools

    An R interface to τ-Argus for statistical disclosure control through cell suppression, enabling seamless integration into R workflows.

    • Input generation: create rda, arb, hst and tab files from R data.
    • Batch execution: generate instructions (arb) and run τ-Argus from the command line.
    • Results retrieval: import τ-Argus outputs directly into R.

    These steps can be performed in a single workflow or independently.


    Additional features

    • Protecting multiple tables simultaneously.
    • Building hierarchical variables from correspondence tables.

    2.3 The rtauargus package

    Tools

    Set up the options as following (using your own location for TauArgus.exe) :

    loc_tauargus <- "Y:/Logiciels/TauArgus/TauArgus4.2.3/TauArgus.exe"
options(rtauargus.tauargus_exe = loc_tauargus)

    03
    Prep your data

    3.1 Check-list

    Prep your data

    From microdata, you need to:

    • Compute all frequencies, values and maximum for all cells (inner and margins) using tabulate_micro_data()
    • Round the frequencies and the values for the purpose of τ-Argus processing
    • Compute primary suppression and booleans to track primary suppression according to each rule if need be
    • Build the hierarchical files .hrc using write_hrc2()

    04
    Protect a table

    4.1 tab_rtauargus()

    Protect a table

    tab_rtauargus() is the heart of the interface between R and τ-Argus.

    TURN_act88_size <- tab_rtauargus(
  tabular=TURN_act88_size,
  dir_name = "tauargus_files/",
  files_name = "TURN_act88_size",
  explanatory_vars = c("A88","SIZE"),
  secret_var = "is_secret_prim",
  value = "VALUE",
  freq = "FREQ",
  totcode = c(A88="Total",SIZE="Total")
)

    Status

    The function returns the data.frame used in the first parameter “tabular” with an additionnal variable Status with the following codes: - V = valid - the only cells whose dissemination is allowed - B = primary secrecy - D = secondary secrecy

    This is a small deviation from the way tau-Argus flags secrecy, as B is commonly the code for dominance.

    05
    Protect linked tables

    5.1 tab_multi_manager()

    Protect linked table

    tab_multi_manager() runs tab_rtauargus() as many times as needed so that all common cells share a common Status. It uses named lists to manage parameters for each table and allow versatility in hierarchy files, total codes, explanatory variables used. Spanning variable names must be consistent throughout the tables, as well as value, freq and secret_var names.

    res <- tab_multi_manager(
  list_tables = list_tab,
  list_explanatory_vars = list_expl,
  dir_name = "tauargus_files/multi",
  hrc = list_hrc,
  totcode = total_codes,
  value = "VALUE",
  freq = "FREQ",
  secret_var = "is_secret_prim"
)

    5.2 tab_multi_manager()

    Protect linked table

    Status and journal

    It returns a list of data.frame, each containing the original data + secrecy variables named is_secret_x, with x ranging from 1 to the number of iterations. This is the last is_secret_prim that contains the final secrecy status as TRUE/FALSE.

    A journal reports on all the process and a summary of secrecy per table.

    06
    Final words

    6.1 Final words

    Final words

    • Remember: rtauargus may run without any warning or error and produce a SDC pattern, that does not mean your tables are protected, if you forgot hierarchies or named differently variables that describe a same concept. Most of the work is what you do before you call tab_multi_manager().
    • If you need assistance, feel free to open issues on our github repo: https://github.com/InseeFrLab/rtauargus
    • We are constantly developping and improving the package functions; for instance, we are working on improving tabulate_micro_data() so that indicators for (n,k) dominance with n>1 could be computed.
    • As of today, rtauargus runs only the original tau-Argus and cannot therefore be used in Linux environments (such as Onyxia); we are looking into removing this limit.
    • Be sure to keep your package up-to-date :-)
